# Android complimentary access

Deploy the standalone access service and verify it with the corresponding signed Android build before supplying reviewer instructions to Google.

An owner may offer a reusable complimentary credential for full Pro access. It confers no access to a pre-existing ledger, customer, device or bank, works independently of the three-day app trial, and never starts a purchase. Every user receives the same build and a holder of the credential receives the same access. There is no reviewer detection or compiled-in master password.

**User path.** Start Wafra, select the desired language and ledger currency, and complete onboarding manually. In Settings → Access code, enter the publisher-provided code. Activate access with Private Mode off and an internet connection. Once active, ordinary Settings and onboarding capture controls still request the user's separate SMS/notification permissions. Opening Pro should show access without asking for checkout. For a clean review, use synthetic information only. Clicking Remove code from this device, or Erase all, removes the local credential and grant. The same active credential works on a newly installed review device. A backup file neither contains nor grants complimentary access.

**Request and storage.** The client sends an HTTPS POST only to the publisher’s separate wafra-access Worker. The code is carried in the Authorization header. The request has no body, financial data, device identifier, or cookies, and redirects are refused. SecureStore holds the credential. A short-lived lease timestamp stays in the encrypted app state so killed-process Android capture can obey the same expiry as the screen. Android backup is disabled and the app's own backup excludes the lease. Customer purchasing and restoring stay tied to Superwall/Google Play and never consume this code.

**Renewal and revocation.** An enrolled foreground Android app refreshes when resumed and before a 15-minute lease runs out. Private Mode suspends online renewal. Offline use ends when the last lease expires. Editing the server digest invalidates the previous bearer on its next online check. Deleting the digest disables the grant. No user or customer records are provisioned. The owner must replace the credential in Play's private review instructions when rotating it. Native bank notification admission and killed-process SMS capture check the complimentary receipt separately from store and trial deadlines. Android also anchors each accepted lease to its boot count and elapsed-real-time clock. It fails closed across reboots until online verification succeeds, and a wall-clock rewind cannot extend the actual lease. A rejected recheck immediately clears the active lease but retains the protected bearer for a bounded retry because throttling uses the same denial response. A shared credential is intentionally reusable: a leak could unlock Pro for another holder until rotation. Rate limiting and a fixed lease bound abuse but cannot identify the intended recipient.

**Operations and release.** The Worker binding, origin, response contract, and offline generation/rotation process are described in [access/README.md](../access/README.md). A blank or failed configuration must never grant access. Credential delivery to Google is a separate privileged step. Do not paste a secret in public artifacts, issue trackers, store listing, analytics or source. The free promo/trial mechanisms in Google Play and purchase-linked Superwall web redemption do not replace reusable review access.

**Minimum release check.** With a non-production test credential on an installed signed candidate verify (1) fresh/expired trial → enter valid code → Pro foreground and background capture, (2) deny either sensitive permission → manual still available, (3) wrong/rotated code → no grant beyond a pre-existing valid lease, (4) Private Mode/offline expiry, (5) erase/restart/restore an old backup → no grant until re-entering the code, (6) store purchase and restore still work independently, and (7) the production Worker and Play-installed build agree on the endpoint, timeout and permissions. Completed host-side tests do not replace these device/provider checks.

**Privacy-policy wording for Android complimentary access.** When you enter a complimentary access code, Wafra sends the code over HTTPS to its dedicated access service on Cloudflare to verify access to Pro. The app stores the code in Android secure storage and checks it again on app use while enrolled. The service stores a hash of the publisher-issued code and returns a short-lived entitlement. It receives no ledger, SMS, transaction, account, or device identifiers from the app. Cloudflare handles the connection, including the network address, to deliver the service. Private Mode pauses verification. Removing the code or erasing the app’s data clears the local credential. No account or purchase is created.
